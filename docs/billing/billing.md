# Billing (Premium via Stripe)

Investments is **Premium-only**. Premium = the Spatie `premium` role. Stripe (Cashier) is the source of truth; the
role is derived from the stored subscription. Card data never touches our server (Stripe Checkout + Customer Portal).

## Flow

1. Free user opens `/investments` -> SPA `premiumGuard` calls `GET /api/billing`; not premium -> `/premium` (upsell).
   The backend enforces it anyway: `permission:view investments` answers 403.
2. `POST /api/billing/checkout {plan: monthly|quarterly|semiannual}` -> Stripe Checkout URL (409 already subscribed, 503 plan not
   configured, 422 bad plan). Success returns to `/premium?checkout=success`, which **polls** `GET /api/billing`
   (2s, 15 tries) until the webhook has made the user premium, then opens Investments.
3. **Only the webhook grants premium**, never the success redirect. `POST /api/stripe/webhook` (Cashier controller,
   signature verified; `RequireStripeWebhookSecret` answers 503 if the secret is empty, because Cashier would
   otherwise skip verification). Cashier stores the subscription, then `SyncPremiumRole` -> `PremiumAccess::sync`.
4. `PremiumAccess::sync`: `subscribed('default')` -> `premium`, otherwise `user`. Idempotent (reads local state), so
   repeated or reordered events are harmless. `past_due` stays premium (Stripe retries the card for a few days, then
   deletes the subscription); `incomplete` (payment not finished) does not. Admins/managers and users with **no**
   subscription row (manual grants from the admin) are never touched.
5. `POST /api/billing/portal` -> Stripe Customer Portal (cancel, change card, invoices/receipts).
6. `billing:sync` (daily 03:00) re-reads every subscription from Stripe and fixes roles after missed webhooks.

## Setup (Stripe test mode first)

`.env` (never committed): `STRIPE_KEY`, `STRIPE_SECRET`, `STRIPE_WEBHOOK_SECRET`, `STRIPE_PRICE_MONTHLY`,
`STRIPE_PRICE_QUARTERLY`, `STRIPE_PRICE_SEMIANNUAL`. Plans: 1, 3 and 6 months (3 and 6 are monthly Prices with `interval_count` 3 / 6). Shown prices: `BILLING_MONTHLY_PRICE` (default 10, EUR), `BILLING_QUARTERLY_DISCOUNT` (default 10 %) and `BILLING_SEMIANNUAL_DISCOUNT` (default 15 %); plan price = monthly x months x (1 - discount), so 10 / 27 / 51 EUR. `GET /api/billing` returns `pricing.<plan> = {price, months, discount}`. Display only: Stripe charges the Price amount, so keep both in sync. Create three recurring Prices in Stripe. Enable the Customer Portal and customer
emails/receipts in Stripe settings. Local webhook: `stripe listen --forward-to localhost:8000/api/stripe/webhook`
(prints the `whsec_...`). Production: add the endpoint for `customer.subscription.*` events.

## Admin

Filament **Billing > Subscriptions** (read-only, `manage users`): user, status, price, ends at. Premium Users stat on
the dashboard. Manual comp: set the role in Users (no subscription row, so webhooks leave it alone). Prices, refunds
and invoices are managed in the Stripe dashboard.

## Invoices

We rely on Stripe receipts/invoices (emailed by Stripe, linked in the Customer Portal). A PDF generated by us would
**not** be a legal invoice in Portugal (needs AT-certified software / ATCUD); decide that before building one.

## Test cases

Automated (`BillingTest`, `billing.service.spec.ts`): free 403 vs premium 200; webhook without secret 503; bad
signature 403 and nothing granted; created -> premium; duplicate delivery -> one subscription; past_due keeps premium;
deleted -> back to `user`; incomplete grants nothing; admin and manual premium untouched; `/billing` shape; checkout
422/503/409; portal 409 without customer; 401 unauthenticated; admin sees subscriptions, manager does not.

Manual (browser, Stripe test mode, card `4242 4242 4242 4242`):

| # | Case | Expected |
| --- | --- | --- |
| M1 | Free user opens `/investments` | redirected to `/premium` |
| M2 | Subscribe monthly, pay | back on `/premium`, "confirming", then Investments opens |
| M3 | Close the tab right after paying, reopen later | still premium (webhook did it) |
| M4 | Cancel at checkout | `/premium?checkout=cancelled`, message, not premium |
| M5 | Card `4000 0000 0000 0341` (renewal fails) | `past_due`, still premium, warning shown |
| M6 | Cancel in portal | premium until period end, "plan ends on" shown, then free |
| M7 | Subscribed user calls checkout again | 409, no second subscription |
| M8 | 3D Secure card `4000 0025 0000 3155` | completes after auth; abandoned -> stays free |
| M9 | Stripe CLI resend of an old event | role unchanged/correct |
| M10 | Admin panel Subscriptions list + filter | shows the new subscription |

## Known limits

- Existing free users lost Investments with no grace period.
- No VAT/Stripe Tax and no own invoice PDF yet (see Invoices).
- No trial and no plan switching beyond the Stripe portal.
